# Paper digest — 2607.14890 Proof-or-Stop / evidence-gated lifecycle control

## 1. Abstract (compressed) `[Evidenced — abs HTML summary; Atom rate-limited]`

Autonomous coding agents execute multi-step work, but lifecycle labels
(`reviewed`, `tested`, `done`, `ready-to-merge`) stay **claims** until a
downstream gate decides they are supported by **current** evidence. The authors
present **Proof-or-Stop Lifecycle Control**: transitions advance only when
fresh, tracked-source-state-bound, mechanically verifiable evidence satisfies
the gate. Agent outputs may propose claims; they do not constitute lifecycle
state. “Proof” here means gate-admissible evidence under a stated trust model,
**not** semantic program correctness. Instantiated in an open-source
Proof-or-Stop implementation; evaluated via mechanism tests, a powered
control-policy ablation (9,240 cells), and operated self-application
(565 stories / 1,007 findings). Unattended-loop engine: 10/10 scenarios, zero
false-`done`; local-key receipt bundles: 18 tamper classes, zero false accepts
in the tested suite. Pre-registered A4-vs-A2′ contrast cut visible-pass /
hidden-fail amplification from 31/1800 to 2/1800 (+1.6pp not-amplified,
95% CI [0.8, 2.5]). Limits: one model family, 24 ablation tasks, self-hosted
corpus.

## 4. Methodical understanding (methodological + systems/empirical checklist)

### Method / formal objects `[Evidenced — §3]`

1. **Objects and relations**  
   - Tracked source state \(H\) with identities over `git ls-tree`, lifecycle
     metadata excluded so writeback does not perturb the binding:  
     \(\mathsf{materialHash}(H)=\mathrm{SHA256}(\mathrm{canon}(\text{tracked tree}\setminus\text{metadata}))\),  
     \(\mathsf{headHash}(H)=\text{commit identity of }H\),  
     \(\mathsf{storyFilesHash}(H)=\mathrm{SHA256}(\mathrm{canon}(\text{story-owned files}))\) (Eq. 1).  
   - Evidence binding  
     \(\beta(E)=\langle\mathsf{materialHash}_E,\mathsf{headHash}_E,\mathsf{storyFilesHash}_E,\mathsf{policyHash}_E,\mathsf{commandSetHash}_E\rangle\).  
   - Executed-action receipt identity  
     \(\rho(E)=\langle\mathrm{cmd},\mathrm{args},\mathrm{cwd},\mathrm{exit},\mathsf{outputDigest}\rangle\).  
   - Gate predicate (Eq. 2):  
     \(\mathrm{Admissible}(E,c,H)\equiv\mathrm{Fresh}\land\mathrm{Complete}\land\mathrm{IntegrityVerified}\land\mathrm{ProducerAuthorized}\land\mathrm{ExecutionAttested}\land\mathrm{Supports}\land\mathrm{OutcomeAccepted}\).  
   - \(\mathrm{Fresh}\) rechecks material / head / story-file bindings against live \(H\); \(\mathrm{Complete}\) covers policy and command-set bindings; \(\mathrm{ExecutionAttested}\) consumes ρ fields.

2. **Proven vs assumed**  
   - **Shown in tested suites (empirical, not universal theorems):** no
     false-`done` on 10/10 engine-contract scenarios; 18 tamper classes rejected
     with zero false accepts; A4 gated loop vs A2′ naive loop amplification drop
     on injected cells; operated corpus volumes and resolution rate
     `[Evidenced — §§5–8, 13]`.  
   - **Assumed / scoped:** single-host local-key trust for signed receipts;
     “proof” ≠ semantic correctness; hashes are **not** full executable-state
     attestation (deps, toolchain, env, untracked files need extra digests)
     `[Evidenced — §3]`.  
   - **No decidability/complexity results** in the STEAD sense `[Confirmed — section map]`.

3. **Plant / measure / false-green**  
   - **Plant:** self-hosted autonomous-coding lifecycle + unattended loop +
     local-key receipt bundles.  
   - **Measure:** false-`done` / false-accept tamper rates; visible-pass /
     hidden-fail amplification; self-application finding resolution.  
   - **False-green risk for our Definition of Ready:** treating their ablation
     or corpus as Accept for Spring / doc-engine trees; renaming Supply-chain
     Levels for Software Artifacts / in-toto as “Proof-or-Stop”; Adopt of a
     missing public engine as merge System of Record.

4. **Public artifact / anti-bogus**  
   - Paper points to `https://github.com/Proof-or-Stop` and tag `arxiv-v1`
     `[Evidenced — Reproducibility]`. Org API lists only `Proof-or-Stop/.github`
     (profile stub); **no engine repository** at audit time → product
     **github_adopters_status: none** / exact engines **0**
     `[Confirmed — FREEZE; entity adoption audit; live org listing this session]`.

5. **Novelty vs packaging**  
   - Algorithm class: freshness-bound β + receipt ρ + Admissible gate as
     lifecycle control plane. Packaging: operated engine + self-application
     corpus. Closest 2026 kin: Agentic Agile-V, ResearchLoop (different domains;
     authors claim tighter code-state freshness).
